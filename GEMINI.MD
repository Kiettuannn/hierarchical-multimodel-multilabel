# Project Coding Instructions

## 1. Language Requirements

- All source code comments MUST be written in English.
- NEVER write Vietnamese comments.
- All docstrings and documentation added to source code MUST be in English.
- Use clear, professional, and technically accurate language.

## 2. Commenting Standards

- Write meaningful comments that explain WHY something is done, not merely WHAT the code does.
- Document complex algorithms, non-obvious decisions, important business rules, and edge cases.
- Add clear docstrings to public classes, functions, and methods where appropriate.
- Explain function parameters, return values, and raised exceptions when useful.
- Avoid redundant comments that simply repeat the code.
- Keep comments concise, informative, and maintainable.
- Update existing comments when modifying related logic.

## 3. No Icons or Emojis

- NEVER use emojis, decorative icons, or Unicode symbols for decoration.
- Do not include emojis in source code, comments, documentation, logging messages, or terminal output.
- Use plain text labels such as INFO, WARNING, ERROR, SUCCESS.
- Do not add decorative symbols to headings or generated explanations.
- Preserve icons that are functionally required by an existing user interface unless explicitly asked to remove them.
